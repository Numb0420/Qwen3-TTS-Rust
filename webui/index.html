📖 API 使用说明

HTTP API (非流式):

POST /api/tts

Body: {"text": "你好", "speaker": "39", "temperature": 0.7, "seed": 43, "volume": 50, "speed": 50}


WebSocket API（流式输出）：

连接地址：ws://192.168.110.76:3000/api/tts/stream；本机可用 ws://127.0.0.1:3000/api/tts/stream。端口与网页相同；HTTPS 页面使用 wss:// 和对应的 HTTPS 服务地址。

连接成功后，发送 JSON 文本消息：

{"text": "你好。", "speaker": "39", "temperature": 0.7, "top_k": 50, "top_p": 1, "seed": 43, "volume": 50, "speed": 50}

服务端持续返回二进制音频消息：24 kHz、单声道、32 位浮点 PCM、小端字节序，没有 WAV 文件头。客户端按接收顺序连续播放；音频包边界不代表句子边界。

文本消息 segment_done 表示一条文本的音频已发送完；done 表示全部音频已发送完。错误消息为 JSON，例如 {"error":"错误原因"}。客户端收到 done 后，仍需播放完已收到的音频。


结束文本输入：

同一连接可以依次发送多条 JSON 合成请求。全部文本发送完后，发送纯文本 end（不是 JSON 字符串，也不是 {"type":"end"}）。服务端继续完成已提交文本，最后返回 done；发送 end 后不能再追加文本。

单次合成示例：socket.send(JSON.stringify({text:"你好。",speaker:"39",temperature:0.7,seed:43})); socket.send('end');


停止流式合成与播放：

关闭正在合成的 WebSocket：socket.close(1000, 'stop');。服务端收到断开后取消该连接的剩余合成；客户端同时停止播放器并清空尚未播放的音频。例如使用 Web Audio 时，关闭该次播放的 AudioContext：audioContext.close();。再次合成时创建新连接和播放器。

停止通过 WebSocket 断开实现，目前没有单独的 HTTP 停止接口，也没有 stop 消息指令。end 只结束文本输入，不会中断合成或播放。


上传自定义说话人：

POST /api/speakers/upload，multipart/form-data 字段：name、ref_text、audio（WAV 文件）。成功后需要重启服务才会加载。

⚠️ 注意事项

合成出现漏字或发音不自然时，可以检查文本末尾是否有句号、问号等标点，补齐后再试。即使指定了拼音，句末标点也可能影响实际读音。

例如“原作者”读不清时，可选中整个词，用“指定读音”填入 yuán zuò zhě；这个短句还需要保留句末的“。”，避免“原”的声调不准。
